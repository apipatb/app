# ✨ Version 2.1 Features

## 🎉 What's New in v2.1

### 1. 📄 Pagination & Sorting

ทุก list endpoints ตอนนี้รองรับ pagination และ sorting แล้ว!

**Query Parameters:**
- `page` - หมายเลขหน้า (default: 1)
- `limit` - จำนวนรายการต่อหน้า (default: 20, max: 100)
- `sort` - เรียงลำดับ (ใช้ `-` สำหรับ descending)

**ตัวอย่าง:**

```bash
# Page 1, 20 items per page, sorted by newest first
GET /api/customers?page=1&limit=20&sort=-createdAt

# Page 2, 50 items, sorted by name A-Z
GET /api/customers?page=2&limit=50&sort=name

# Multiple sort fields
GET /api/customers?sort=-createdAt,name
```

**Response Format:**

```json
{
  "success": true,
  "message": "Success",
  "data": [...],
  "pagination": {
    "total": 150,
    "page": 1,
    "limit": 20,
    "totalPages": 8,
    "hasNextPage": true,
    "hasPrevPage": false,
    "nextPage": 2,
    "prevPage": null
  }
}
```

### 2. 🔍 Advanced Search & Filtering

ค้นหาข้อมูลได้ง่ายขึ้นด้วย search parameter

**ตัวอย่าง:**

```bash
# ค้นหา customers ด้วย name, phone, หรือ email
GET /api/customers?search=สมชาย

# ค้นหาและเรียงลำดับ
GET /api/customers?search=สมชาย&sort=name
```

**Search Fields:**
- **Customers**: name, phone, email
- **Services**: name, description (coming soon)
- **Orders**: orderNumber, customer name (coming soon)

### 4. 💚 Enhanced Health Checks

Health check endpoints ที่ดีขึ้น พร้อมสำหรับ Kubernetes!

**Endpoints:**

```bash
# 1. Basic Health Check
GET /health
{

  "version": "2.1.0",
  "timestamp": "2025-01-15T10:30:00.000Z",

# 2. Detailed Health Check (with dependencies)
GET /health/detailed
{
  "success": true,
  "timestamp": "2025-01-15T10:30:00.000Z",
  "uptime": 3600,
  "environment": "production",
  "version": "2.1.0",
  "services": {
    "mongodb": {
      "status": "healthy",
      "state": "connected",
      "host": "mongodb.railway.internal",
      "name": "laundry_db"
    },
    "redis": {
      "status": "healthy",
      "latency": "5ms",
      "connected": true
    }
  },
  "memory": {
    "rss": "125MB",
    "heapTotal": "80MB",
    "heapUsed": "65MB",
    "external": "5MB"
  }
}

# 3. Readiness Probe (Kubernetes)
GET /health/ready
# Returns 200 if all dependencies are ready
# Returns 503 if not ready

# 4. Liveness Probe (Kubernetes)
GET /health/live
# Returns 200 if app is alive
```

**Use Cases:**
- **Monitoring**: เช็คสถานะ services แบบ real-time
- **Kubernetes**: Readiness และ Liveness probes
- **Load Balancer**: Health check endpoints
- **Debugging**: ดูสถานะ dependencies

**Kubernetes Deployment Example:**

```yaml
livenessProbe:
  httpGet:
    path: /health/live
    port: 3000
  initialDelaySeconds: 30
  periodSeconds: 10

readinessProbe:
  httpGet:
    path: /health/ready
    port: 3000
  initialDelaySeconds: 10
  periodSeconds: 5
```

## 🚀 Migration Guide

### From v2.0 to v2.1

**1. Update Controllers (if custom)**

```javascript
// Old
const customers = await Customer.find().sort({ createdAt: -1 });
res.json({ success: true, data: customers });

// New
const { page, limit, skip } = parsePagination(req.query);
const sort = parseSort(req.query.sort);
const result = await paginate(Customer.find(filter), { page, limit, skip, sort });
return response.successWithPagination(res, result.data, result.pagination);
```

**2. Update API Calls (Frontend)**

```javascript
// Old
fetch('/api/customers')

// New (with pagination)
fetch('/api/customers?page=1&limit=20&sort=-createdAt')

// Handle pagination metadata
const { data, pagination } = await response.json();
console.log(`Page ${pagination.page} of ${pagination.totalPages}`);
```

**3. Health Check Monitoring**

```javascript
// Old
fetch('/health')

// New (detailed)
fetch('/health/detailed')

// For Kubernetes
# Liveness: /health/live
# Readiness: /health/ready
```
